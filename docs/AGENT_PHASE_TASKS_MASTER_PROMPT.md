# Мастерпромпт: декомпозиция фазы дорожной карты в `tasks/`

**Назначение:** запрос к агенту поставить **исполнимые подзадачи** для выбранной **фазы** из [`tasks/000-full-service-aprilhub-roadmap/PLAN.md`](../tasks/000-full-service-aprilhub-roadmap/PLAN.md) и сохранить их в **отдельных папках** `tasks/<NNN-slug>/` (постановки по [`AGENT_TASK_TEMPLATE.md`](./AGENT_TASK_TEMPLATE.md)).

**Отличие от** [`AGENT_MASTER_PROMPT.md`](./AGENT_MASTER_PROMPT.md): здесь фокус на **планировании и файлах задач**, а не на написании кода.

---

## Как использовать

1. Скопируй блок **«Промпт»** ниже в чат.
2. В секции `PHASE SPEC` укажи номер фазы и при необходимости: только «Сначала» / «Затем», подфазу (например 4.1), лимит числа подзадач, ограничения по слоям (backend only и т.д.).

---

## Промпт (копировать отсюда)

```md
Ты работаешь в репозитории **April Profile / April Service**. Задача — **не писать код**, а **поставить исполнимые подзадачи** для выбранной **фазы** дорожной карты и **сохранить их в отдельных папках** под `tasks/`, чтобы ими можно было пользоваться как отдельными тикетами для агента-исполнителя (по [`docs/AGENT_MASTER_PROMPT.md`](./AGENT_MASTER_PROMPT.md)).

### Обязательное чтение перед разбиением

1. [`tasks/000-full-service-aprilhub-roadmap/PLAN.md`](../tasks/000-full-service-aprilhub-roadmap/PLAN.md) — раздел **«Фаза N — …»** (и подразделы вроде 4.1 / 4.2, если фаза составная), плюс блок **«Зависимости»** для этой фазы и общий **граф фаз** внизу файла.
2. [`tasks/README.md`](../tasks/README.md) — именование папок, состав файлов (`TASK.md`, опционально `PLAN.md`, `REPORT.md`, `notes.md`, `attachments/`).
3. [`docs/AGENT_TASK_TEMPLATE.md`](./AGENT_TASK_TEMPLATE.md) — структура постановки для каждой подзадачи.
4. [`docs/AGENT_ARCHITECTURE_CONTEXT.md`](./AGENT_ARCHITECTURE_CONTEXT.md) — стек и границы; не предлагай замену ключевых технологий без явного запроса.
5. При необходимости: [`docs/DEPLOYMENT_STRATEGY.md`](./DEPLOYMENT_STRATEGY.md), [`docs/TESTING_STRATEGY.md`](./TESTING_STRATEGY.md), ADR и дизайн, на которые ссылается `PLAN.md` для этой фазы.

### Что считать «фазой N»

- Бери формулировки **«Сначала»** и **«Затем»** из соответствующего раздела `PLAN.md` как **минимум два уровня инкремента** (если по смыслу это два разных PR или два разных фокуса).
- Если в фазе есть подпункты (например **4.1** и **4.2**), **каждый логический поток** (платформа vs продукт) — отдельная подзадача или группа подзадач с явной связью в мета-полях.
- **Не дублируй** весь текст фазы в каждой задаче: в **Цель** и **Контекст** дай сжатую формулировку + **прямую ссылку** на соответствующий абзац `PLAN.md` (относительный путь из папки задачи).

### Правила декомпозиции

- Размер подзадачи: **один смысловой инкремент**, который укладывается в **один PR / одну ветку** по практике из `PLAN.md` (короткие задачи с явным критерием готовности).
- Для каждой подзадачи явно укажи:
  - **зависимости** (какие другие подзадачи или внешние фазы должны быть готовы);
  - **что является заглушкой/mock** до появления внешнего API или стенда;
  - **критерии приёмки**, проверяемые командами из репо (`make …`, `go test …`, и т.д. — по мере актуальности; если кода ещё нет, опиши ожидаемые команды из [`docs/TESTING_STRATEGY.md`](./TESTING_STRATEGY.md) как целевые).
- **Технические ограничения** проекта переноси в каждую задачу, где релевантно: Atlas для миграций, Keycloak для RBAC, синхронизация OpenAPI с REST и т.д. (как в шаблоне задачи).

### Именование и нумерация папок

- Формат: `NNN-<краткий-slug-latin>` по [`tasks/README.md`](../tasks/README.md).
- **NNN:** возьми **следующие свободные** номера после уже существующих папок в `tasks/` (например, если заняты `000-…`, `001-…`, `002-…`, новые начинай с `003-…`, без пропусков в пределах создаваемого набора, если не оговорено иначе).
- **slug:** короткий, уникальный, по сути работы (например `phase-3-asynq-outbox`, `phase-1-go-health-oidc`).

### Содержимое каждой новой папки

- Обязательно **`TASK.md`**: полная структура по [`docs/AGENT_TASK_TEMPLATE.md`](./AGENT_TASK_TEMPLATE.md) (Мета, Цель, Контекст, Входит / Не входит, Ограничения, Критерии, Команды проверки, Результат в отчёте).
- В **Мета** каждой подзадачи укажи:
  - ссылку на родительскую дорожную карту: [`tasks/000-full-service-aprilhub-roadmap/`](../tasks/000-full-service-aprilhub-roadmap/) и конкретную фазу в `PLAN.md`;
  - при необходимости — связь с другими новыми `NNN-…` (ID соседних подзадач).
- **`PLAN.md`** создавай **только** для подзадач, которые нетривиальны (несколько слоёв, неочевидный порядок, высокий риск) — по [`docs/AGENT_PLAN_TEMPLATE.md`](./AGENT_PLAN_TEMPLATE.md). Для узких задач достаточно `TASK.md`.

### Обновление индекса

- Обнови [`task_list.md`](../task_list.md) в корне: добавь строки в подходящий раздел (например **Разработка** или **Планирование**) со **ссылками** на каждую новую папку и кратким названием; отметь зависимости текстом, если в `task_list` это принято.

### Результат работы в этом запросе

1. Список созданных путей `tasks/NNN-slug/` с одним предложением «что внутри».
2. Таблица или список **порядка выполнения** с учётом зависимостей фазы и подзадач.
3. Краткое примечание, если для фазы нужны **ручные контрольные точки** (доступы, согласование с AprilHub, секреты CI) — по духу раздела «Как вести работу с агентом» в `PLAN.md`.

--- PHASE SPEC ---
Фаза для декомпозиции: **N** (и при необходимости уточнение: только «Сначала», только «Затем», или вся фаза целиком).
Дополнительные ограничения от пользователя: …
--- PHASE SPEC END ---
```
