# ADR-0006: Нижняя mobile-панель (`AprilMobileShellBar`) — стратегия A, стек владельца, AprilHub

- **Дата:** 2026-05-03 (обновлено: нормативный контракт и стратегия A)
- **Статус:** принято
- **Контекст:** В экосистеме April **единый фронт** собирается в **AprilHub** из layout и **вставок** npm-виджетов `@april/*-ui` ([`FRONTEND_STRATEGY.md`](../FRONTEND_STRATEGY.md), ADR-0004). На узком viewport нижняя капсула **`AprilMobileShellBar`** — основной слот действий (DS §8). Возможны **произвольная глубина** вложенности (виджет внутри виджета, несколько sheet), а также **глобальный** dock Hub. Без явной политики команды получают конкурирующие капсулы, неработающий **«Назад»** и рассинхрон vendored `@april/ui`.

- **Решение (стратегия A — принята по умолчанию):**
  1. **Стек владельца панели:** в каждый момент в **одной ветке UI** (один «слот» у нижнего края контентной области) пользователю показывается **не более одной** нижней капсулы, отражающей **текущий активный контекст** этой ветки. При открытии верхнего слоя (sheet, полноэкранный шаг, вложенный виджет) **родитель обязан** скрыть или размонтировать свою панель в этой ветке (например `CardListColumn.hideMobileShellBar`, локальный state), а **вершина стека** монтирует свою `AprilMobileShellBar` при необходимости.
  2. **Не фиксировать «ровно N слоёв»** в архитектуре: число логических уровней не ограничено; ограничение — **норма «один активный контекст в одной капсуле»** (DS §8) и **одна видимая капсула на ветку** для стратегии A.
  3. **AprilHub (host)** может держать **дополнительную** глобальную нижнюю панель приложения; это **отдельный** продуктовый слой. Согласование с панелью виджета — в [`WIDGET_INTEGRATION_CHECKLIST.md`](../WIDGET_INTEGRATION_CHECKLIST.md). Альтернатива «одна капсула на всё приложение» (делегирование действий только в Hub) **не** является текущим обязательным контрактом v1; вводится отдельным ADR и версией контракта.
  4. **«Назад»:** в стратегии A **сначала** снимается **верхний** модальный/листовый слой в ветке виджета (`onClose` sheet, `leading` у панели детали при overlay и т.д.), **затем** host обрабатывает выход с маршрута (intent). **Android system back** не должен перехватываться Hub раньше, чем закроется открытый `AprilVaulBottomSheet`, если лист объявляет обработку back.
  5. **Поставка `@april/ui`:** реализации в shell (Hub, сервисные shell) **обязаны** содержать актуальные пропы примитивов (например `CardListColumn.hideMobileShellBar`); иначе виджеты передают контрактные пропы в runtime, который их игнорирует.

- **Последствия:** Виджеты остаются **переносимыми** npm-пакетами; Hub не обязан знать внутреннюю state machine каждого виджета для нижней панели. Цена — дисциплина вложенности и чеклисты интеграции; при ошибке — визуальный «двойной низ».

## Альтернатива B (не принята как default)

**Делегирование:** единственная `AprilMobileShellBar` в Hub, виджеты регистрируют descriptor действий. Требует общего протокола Hub ↔ все `@april/*-ui`, согласованных релизов. Допустима как **целевой** режим для отдельных продуктов после отдельного ADR.
