# 009 — Интеграционные тесты с PostgreSQL/Redis и миграциями Atlas

## Что поменялось

В этом шаге в репозитории появился базовый интеграционный контур backend:

- добавлен отдельный пакет интеграционных тестов с тегом `integration`;
- в тестах через Testcontainers поднимаются реальные PostgreSQL и Redis;
- перед проверками автоматически применяются миграции через `atlas migrate apply` из `atlas/migrations`;
- добавлены проверки, что ключевые таблицы реально созданы миграциями;
- добавлен smoke-интеграционный тест для `GET /healthz` и `GET /readyz` на тестовом HTTP-сервере с реальными зависимостями;
- в `Makefile` добавлена команда `make integration-test`.

## Зачем это команде

- Ошибки в миграциях и подключениях к Postgres/Redis ловятся до деплоя.
- Проверяется не "мок-сценарий", а реальный путь с контейнерами и Atlas.
- Появился воспроизводимый запуск интеграционных тестов локально и в CI, где доступен Docker.

## Границы задачи

Сделано в рамках 009:

- базовый интеграционный набор для инфраструктурного каркаса фазы 1;
- применение миграций только через Atlas;
- документация по запуску integration-тестов.

Осознанно оставлено на follow-up:

- интеграция с реальным Keycloak в каждом PR (можно добавить позднее отдельным job/профилем);
- расширение покрытия на доменные API фазы 2.

## Как проверить без чтения кода

```bash
go vet ./...
go test ./...
go test -tags=integration ./...
make openapi-lint
make docs-build
```

Что считать успехом:

1. `go test -tags=integration ./...` завершается без ошибок.
2. В логике тестов миграции Atlas применяются к временной БД в контейнере.
3. Проверка `/readyz` на тестовом сервере с реальными Postgres/Redis возвращает `200`.
