# 004 — Go-модуль, Atlas и стартовая схема БД

## Что болело

До этой задачи сервис был в основном документационным шаблоном. Нужна была минимальная "живая" backend-основа:

- модуль и структура Go-сервиса;
- управляемые миграции через Atlas;
- tenant-ориентированная базовая схема БД.

## Что сделали

- Инициализировали Go модуль и каркас монолита (`cmd`, `internal`).
- Добавили Atlas-конфиг и первую миграцию.
- Создали стартовые таблицы (`tenants`, `entities`, версии, события и т.д.).
- Добавили цели Makefile и CI-шаги для `go vet/go build` и `atlas migrate validate`.
- Подготовили локальную Postgres-среду через compose-профиль.

## Что получили

- Технический фундамент для следующих API-задач.
- Воспроизводимые миграции (без "ручного SQL на сервере").
- Базовую tenant-структуру данных под дальнейший CRUD и доменную логику.

## Что важно для команды

- Изменения схемы теперь идут через Atlas-процесс.
- Есть единый путь проверки в CI.
- Можно локально поднимать БД и проверять миграции теми же командами.

## Ограничения

- Это заготовка: без полного доменного API и без интеграционных тестов всей цепочки.
