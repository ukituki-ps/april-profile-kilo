# Планирование — дизайн AprilProfile и ADR

## Что сделали

Отдельным блоком закрыли архитектурное планирование продукта:

- дизайн модуля `AprilProfile`;
- ключевые ADR по границам и модели данных;
- принципы мультитенантности и интеграции.

## Что это дало "на пальцах"

- Все понимают, где граница ответственности сервиса.
- Договорились про базовые сущности и инварианты.
- Зафиксировали архитектурные решения так, чтобы не спорить заново в каждой задаче.

## Почему это критично

Если не зафиксировать дизайн заранее, реализация уходит в разные стороны:

- backend делает одну модель,
- frontend опирается на другую,
- интеграции с Hub ожидают третью.

Документы и ADR выравнивают эти ожидания.

## На выходе для разработки

- Задачи 004+ уже делались на стабильном архитектурном фундаменте.
- Меньше "скрытых развилок" в коде.
- Проще ревьюить изменения: есть куда сверяться.
