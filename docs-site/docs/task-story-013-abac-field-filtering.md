# 013 — ABAC: фильтрация выдачи профиля по сегментам полей

## Что поменялось

- Для **GET**-запросов, возвращающих профиль (`ProfileSnapshot`), сервис может **урезать** поле `document` (и записи в `_meta.authority`) в зависимости от **realm-ролей** в access token Keycloak.
- Политика задаётся переменной окружения **`ABAC_SEGMENT_ACCESS_JSON`**: для каждого **сегмента** (namespace в документе) перечислены роли, которым этот сегмент разрешён. Если переменная **пустая**, фильтрация **не применяется** (как раньше).
- **Сегмент `default`** — это корневые «плоские» поля профиля (строки, числа и т.д.). **Вложенный объект** с именем ключа, например `hr` или `security`, — это отдельный сегмент с тем же именем.

## Зачем это нужно

В мультитенантном сервисе разные потребители (интеграции, роли пользователей) не должны видеть одни и те же чувствительные блоки данных. **Tenant-изоляция** по-прежнему обязательна; ABAC добавляет **второй слой**: даже внутри тенанта выдача полей зависит от ролей в IAM, без дублирования отдельной «кастомной» модели прав в обход Keycloak.

## Границы задачи

Не входило: редактор политик в UI, OPA/внешний PDP, события при смене политик.
