# Задача 038: исполнить внешнюю задачу 039 в `april-work` с отчётом в двух репозиториях

## Мета
- **Репозиторий выполнения:** `april-work` (внешний репозиторий-источник задачи).
- **Карточка трассировки:** текущая карточка в `april-profile-1` (для локальной фиксации работы и результатов).
- **Целевая внешняя задача:** `task 39` в `april-work`.
- **Приоритет:** высокий.
- **ID / ветка:** создать и указать при выполнении в `april-work`.
- **Связанные документы:** документация `april-work`, связанная с `task 39` (обязательно изучить перед реализацией).

## Цель
Реализовать `task 39` в репозитории `april-work` на основе их актуальной документации и зафиксировать результаты в двух местах:
1) отчёт в `april-work` по их процессу;
2) зеркальный отчёт в этой задаче (`tasks/038.../REPORT.md`) с ссылками на артефакты.

## Контекст для агента
- Источник требований и критериев приёмки — `task 39` в `april-work`.
- Перед изменениями нужно прочитать документацию `april-work`, которая относится к целевой задаче, и строго следовать их рабочим правилам.
- Эта карточка в `april-profile-1` нужна для прозрачной трассировки внешнего исполнения.

## Входит в объём
- Найти и изучить в `april-work`:
  - постановку `task 39`;
  - все релевантные разделы документации (архитектура, workflow, кодстайл, тесты, деплой/релиз, если применимо).
- Реализовать `task 39` в `april-work` в полном объёме согласно их acceptance criteria.
- Прогнать релевантные проверки/тесты в `april-work`.
- Подготовить и опубликовать отчёт о выполнении в `april-work` (по принятому там формату).
- Подготовить зеркальный отчёт в `april-profile-1` с:
  - ссылками на PR/коммиты/ветку в `april-work`;
  - перечнем выполненных критериев;
  - результатами тестов;
  - рисками, ограничениями и follow-up.

## Не входит в объём
- Любые изменения вне рамок `task 39` в `april-work`, не требуемые для её завершения.
- Несогласованные рефакторинги "по пути", не влияющие на acceptance критерии задачи.

## Заглушки и внешние зависимости
- Если часть окружений/интеграций `april-work` недоступна, зафиксировать это как ограничение в обоих отчётах.
- Для временных блокеров использовать согласованный fallback-процесс из документации `april-work`.

## Технические ограничения
- Не отступать от архитектурных и процессных правил, закреплённых в документации `april-work`.
- Не внедрять breaking-изменения без явного согласования, если это запрещено правилами/процессом `april-work`.

## Критерии готовности (acceptance)
- [ ] В `april-work` выполнены все критерии приёмки `task 39`.
- [ ] В `april-work` создан отчёт о выполнении с проверяемыми артефактами (PR/коммиты/тесты).
- [ ] В `april-profile-1` обновлён `tasks/038-phase-4d-execute-external-task-039-april-work/REPORT.md` как зеркало результата.
- [ ] В зеркальном отчёте явно указано, где именно в `april-work` лежит оригинальный отчёт и какие проверки пройдены.

## Проверка (команды)
```bash

# <команды берутся из task 39 и документации april-work>
# <минимум: линт/тесты/проверки, требуемые их acceptance>
```

## Результат в отчёте
- Ссылка на `task 39` в `april-work`.
- Ссылка на ветку/PR и ключевые коммиты в `april-work`.
- Краткая сводка реализованного объёма и прохождения acceptance.
- Результаты тестов/проверок и список известных ограничений.
- Явная ссылка на оригинальный отчёт в `april-work` и зеркальный отчёт в этом репозитории.
