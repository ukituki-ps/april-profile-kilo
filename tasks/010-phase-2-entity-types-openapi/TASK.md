## Цель
В сервисе есть управляемый каталог типов сущностей (черновик/публикация схем), а OpenAPI описывает API каталога и модель схем так, чтобы следующий инкремент с CRUD и версиями профиля использовал уже стабильный контракт.

## Контекст для агента
- Опора на фазу 2, блок «Сначала» в [`../000-full-service-aprilhub-roadmap/PLAN.md`](../000-full-service-aprilhub-roadmap/PLAN.md).
- Технологические ограничения: Go REST, PostgreSQL, Keycloak, OpenAPI в одном изменении при изменении контракта.

## Входит в объём
- API и модель хранения для типов сущностей с жизненным циклом минимум `draft -> published`.
- Валидация схемы типа при публикации (минимум структурная и инварианты из ADR).
- OpenAPI: эндпоинты каталога типов и примеры ответов/ошибок.
- Подготовка почвы для API профилей: идентификатор типа, версия схемы, статус публикации.

## Не входит в объём
- Полный CRUD профиля и append-only версии (это [`011`](../011-phase-2-entity-crud-versioning/)).
- Authority/merge/конфликты (это [`012`](../012-phase-2-authority-merge-conflicts/)).
- ABAC фильтрация полей в выдаче (это [`013`](../013-phase-2-abac-field-filtering/)).

## Заглушки и внешние зависимости
- Если внешний реестр схем/валидации не готов, допустим локальный валидатор и внутренняя модель схемы как временная реализация; это фиксируется в `REPORT.md`.
- Если отсутствует стабильный контракт внешних систем на поля, разрешён минимальный пилотный набор атрибутов с явным флагом расширения.

## Технические ограничения
- Миграции БД только через Atlas.
- Tenant-изоляция обязательна: доступ к типам в контексте текущего `tenant_id`.
- RBAC через Keycloak, без замены IAM-подхода.
- OpenAPI и реализация синхронизированы в одном PR.

## Критерии готовности (acceptance)
- [ ] Для tenant доступны операции создания черновика типа и публикации типа.
- [ ] Повторная публикация/некорректная схема обрабатываются предсказуемыми кодами ошибок.
- [ ] OpenAPI содержит контракт каталога типов и проходит проверку совместимости.
- [ ] Тесты на базовый путь каталога типов зелёные (unit/integration по возможности).
