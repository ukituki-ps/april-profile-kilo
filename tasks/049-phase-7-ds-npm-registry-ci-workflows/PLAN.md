## Порядок работ (шаги)

1. Сверить с april-worker: переменные для `npm`/`pnpm` и GitHub Packages.
2. В каждом job, где выполняется `npm ci` в `frontend/`, добавить `env: NODE_AUTH_TOKEN: ${{ secrets.<NAME> }}` (уточнить `<NAME>` с владельцем org; часто `GITHUB_TOKEN` достаточно для `packages:read` в том же org при правильных permissions workflow).
3. Убедиться, что `permissions:` у workflow включают чтение packages при использовании `GITHUB_TOKEN`.
4. Если `ds:prepare` остаётся для копирования ассетов: либо оставить лёгкий шаг без `pnpm build`, либо перенести ассеты в репозиторий — решение зафиксировать в **050**.
5. Прогнать workflow на ветке PR; оформить `REPORT.md`.

- **Риск:** `GITHUB_TOKEN` не имеет доступа к другому org/repo пакетов → отдельный PAT в secrets.
- **Откат:** revert workflow; временно вернуть обязательный submodule (нежелательно после эпика).
