# План: Пакет `@april/profile-ui`, OpenAPI-клиент, встраиваемый компонент

- **Задача:** [`TASK.md`](./TASK.md)
- **Дата плана:** 2026-04-22
- **Статус плана:** черновик

## Исходные допущения
- OpenAPI в `openapi/openapi.yaml` отражает стабильный REST фазы 2.
- Дизайн-система доступна через существующий submodule / workspace (`frontend/`).

## Порядок работ (шаги)
1. Согласовать **имя пакета** и область публикации (npm scope) с владельцем org; зафиксировать в README.
2. Добавить workspace-пакет (каталог под `packages/` или принятая структура).
3. Подключить **генерацию клиента** (openapi-generator / orval / иной один выбор) и npm-script `generate` из корня OpenAPI.
4. Реализовать **встраиваемый** компонент минимального сценария (чтение + сохранение одной сущности или согласованный MVP).
5. Покрыть MSW+Vitest критическим путём; обновить CI при необходимости.
6. Демо в `frontend/` или story — по минимуму для ручного smoke.

## Затрагиваемые области
| Область | Что меняется (кратко) |
|--------|------------------------|
| Frontend / packages | Новый пакет, генерация клиента |
| OpenAPI | Только если нужны правки для генерации |
| CI | Доп. job или шаги lint/test пакета |

## Риски и откат
- **Риск:** генератор не поддерживает конструкции спеки. **Митигация:** узкий patch спеки или смена генератора — согласовать в PR.
- **Откат:** удаление пакета из workspace; revert скриптов генерации.

## Проверка после выполнения
- Локально: демо-экран вызывает API через сгенерированный клиент (mock или dev).
- CI: зелёные lint/test/build для затронутых пакетов.
