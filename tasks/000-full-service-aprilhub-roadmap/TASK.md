# Задача: дорожная карта рабочего AprilProfile и интеграция с AprilHub

## Мета

- **ID:** `000-full-service-aprilhub-roadmap`
- **Приоритет:** обычный
- **Связанные документы:** [`PLAN.md`](./PLAN.md), [`docs/DESIGN_AprilProfile.md`](../../docs/DESIGN_AprilProfile.md), ADR-0002, ADR-0003, [`docs/FRONTEND_STRATEGY.md`](../../docs/FRONTEND_STRATEGY.md), [`task_list.md`](../../task_list.md)

## Цель

Зафиксировать в репозитории **поэтапный план** вывода AprilProfile из состояния шаблона/дизайна к **полноценному сервису**, интегрированному с **AprilHub** (инфраструктурный контур + BFF/UI), с **понятными рубежами внутри каждой фазы** и с учётом того, что **реализацию вы ведёте вместе с агентом** (короткие задачи, ревью, CI как ворота качества).

## Контекст для агента

- Опора на [`docs/AGENT_ARCHITECTURE_CONTEXT.md`](../../docs/AGENT_ARCHITECTURE_CONTEXT.md), [`README.md`](../../README.md).
- Инварианты продукта уже в [`docs/DESIGN_AprilProfile.md`](../../docs/DESIGN_AprilProfile.md) и ADR; план **не меняет** ADR, а раскладывает реализацию.

## Входит в объём

- Файл [`PLAN.md`](./PLAN.md) с фазами 0–7, зависимостями, рисками, проверками, блоком **«как работать с агентом»**.
- Для каждой фазы — **сначала / затем** (базовый инкремент и расширение), **без** календарных оценок.
- Обновление [`task_list.md`](../../task_list.md) — ссылка на эту задачу.

## Не входит в объём

- Реализация бэкенда, миграций, UI (отдельные задачи в `tasks/` по мере работы).
- Изменения в ADR без отдельного решения команды.

## Технические ограничения

- Стек и границы — как в [`docs/AGENT_ARCHITECTURE_CONTEXT.md`](../../docs/AGENT_ARCHITECTURE_CONTEXT.md).
- Интеграция с AprilHub: [april-worker](https://github.com/ukituki-ps/april-worker) как источник правды по общему observability-контуру; продуктовая связка — BFF Hub + пакеты UI по [`docs/FRONTEND_STRATEGY.md`](../../docs/FRONTEND_STRATEGY.md).

## Критерии готовности (acceptance)

- [ ] В [`PLAN.md`](./PLAN.md) описаны фазы 0–7, зависимости, риски, проверки.
- [ ] Описана модель работы **человек + агент** (роли, размер задач, ручные контрольные точки).
- [ ] Для каждой фазы заданы **сначала** и **затем** без использования термина MVP и **без** оценок по времени.
- [ ] [`task_list.md`](../../task_list.md) содержит ссылку на эту папку задачи.

## Проверка (команды)

Документарная задача; при правках документации:

```bash
make docs-build
```

## Результат в отчёте

После реализации кода по фазам — отдельные `REPORT.md` в подзадачах; для этой задачи достаточно актуальности `PLAN.md` и ссылки в `task_list.md`.
