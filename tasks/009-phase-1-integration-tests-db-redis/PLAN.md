# План: Фаза 1 (часть 6) — базовые интеграционные тесты (PostgreSQL, Redis, Atlas)

- **Задача:** [`TASK.md`](./TASK.md)
- **Дата плана:** 2026-04-21
- **Статус плана:** черновик

## Исходные допущения
- Интеграционные тесты запускаются только при наличии Docker (локально и в CI-окружениях с Docker Engine).
- Миграции схемы в тестах применяются тем же способом, что и в текущем процессе (`atlas migrate apply`), без дублирования SQL в тестовом коде.
- Scope ограничен каркасом backend фазы 1: зависимости (PostgreSQL/Redis), readiness и базовые HTTP-маршруты.

## Порядок работ (шаги)
1. Добавить зависимости `testcontainers-go` и подготовить пакет интеграционных тестов с build tag `integration`.
2. Реализовать test helper: поднятие PostgreSQL и Redis контейнеров, сборка `DATABASE_URL`, запуск Atlas-миграций.
3. Добавить интеграционные тесты: проверка применения миграций (наличие ключевых таблиц) и проверка HTTP `/healthz`/`/readyz` с реальными зависимостями.
4. Добавить удобный запуск через `Makefile` (`go test -tags=integration ./...`).
5. Обновить документацию запуска интеграционных тестов и человекопонятную историю задачи в `docs-site`.
6. Заполнить `REPORT.md` по шаблону и синхронизировать статус в `task_list.md`.

## Риски и откат
- **Риск:** Нестабильность на CI без Docker. → **Митигация:** документировать ограничение и держать интеграционные тесты отдельным контуром (тег `integration`).
- **Риск:** Atlas в тестах не сможет подключиться к контейнерной БД при неверном URL. → **Митигация:** формирование URL из реальных mapped port и отдельная проверка ошибки миграций.
- При необходимости отката: revert изменений задачи 009; схема БД и runtime-код сервиса не изменяются.

- Ручная проверка: успешный запуск интеграционного набора с поднятием PostgreSQL/Redis контейнеров и применением Atlas-миграций.
