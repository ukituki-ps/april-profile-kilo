# Задача 041: выделить из `widget-card` отдельный виджет `Profiles`

## Мета
- **ID / ветка:** `feature/task-041-widget-card-to-profiles-widget`
- **Приоритет:** высокий
- **Связанные документы:** [`task_list.md`](../../task_list.md), [`tasks/040-phase-5-widget-card-layout-modernization/TASK.md`](../040-phase-5-widget-card-layout-modernization/TASK.md), [`tasks/025-phase-4a-profile-profiles-list-crud-widget/TASK.md`](../025-phase-4a-profile-profiles-list-crud-widget/TASK.md), [`docs/WIDGET_CONTRACTS.md`](../../docs/WIDGET_CONTRACTS.md)

## Цель
На базе обновлённого UX из задачи 040 оформить самостоятельный виджет `Profiles`: переиспользовать логику двухколоночного `widget-card`, но вынести её в отдельный публичный компонент/контракт виджета с понятным API и документацией для встраивания.

## Контекст для агента
- Опора на [`docs/AGENT_ARCHITECTURE_CONTEXT.md`](../../docs/AGENT_ARCHITECTURE_CONTEXT.md) и [`README.md`](../../README.md).
- Задача 040 уже внедрила master-detail layout (25/75) и сценарии list/search/filter/pagination/edit/create/delete.
- Требуется продуктово закрепить этот UX как отдельный виджет `Profiles`, а не как локальную реализацию внутри `widget-card`.
- DS-first: использовать существующие компоненты `@april/ui` (включая `CardListColumn`) и текущие паттерны `@april/profile-ui`.

## Входит в объём
- Выделить реализацию `widget-card` из задачи 040 в отдельный виджет `Profiles` (компонент и экспорт в `@april/profile-ui`).
- Уточнить и зафиксировать публичный контракт `Profiles` (props, callbacks, ошибки, состояния загрузки/пустого списка).
- Сохранить UX и функциональность:
  - двухколоночный layout 25/75;
  - список с поиском/фильтрацией/пагинацией;
  - карточка выбранного профиля (просмотр/редактирование);
  - создание профиля через модальное окно и удаление.
- Обновить демо/маршрутизацию, чтобы `Profiles` был отдельным демонстрационным сценарием.
- Обновить документацию по виджету (`README` пакета, docs по контракту/каталогу виджетов, при необходимости docs-site).
- Добавить/обновить тесты для `Profiles` как самостоятельного виджета (рендер, CRUD-флоу, ошибки API, взаимодействие list/detail).

## Не входит в объём
- Изменение backend API-контрактов и OpenAPI, если текущего API достаточно.
- Изменение бизнес-правил авторизации и tenancy.
- Редизайн остальных виджетов (`Instances`, `History`, `Conflict Queue`) вне влияния переименования/выделения `Profiles`.

## Технические ограничения
- Стек: React + TypeScript + Vite + Mantine в рамках текущей архитектуры.
- Переиспользование существующей API-логики и типов обязательно; избегать копипаста между `widget-card` и `Profiles`.
- DS-first: использовать `@april/ui` и существующие паттерны DisignApril, кастомный UI только при обоснованном исключении.
- Не хардкодить секреты/URL; использовать env-конфигурацию проекта.
- Совместимость с BFF/OIDC-потоком AprilHub должна сохраниться.
