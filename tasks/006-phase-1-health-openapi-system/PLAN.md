# План: Фаза 1 (часть 3) — `/healthz`, `/readyz` и синхронизация OpenAPI

- **Задача:** [`TASK.md`](./TASK.md)
- **Дата плана:** 2026-04-21
- **Статус плана:** согласован

## Исходные допущения
- HTTP-роутер уже поднят в `internal/httpapi` и используется `net/http` + `ServeMux`.
- На текущем инкременте `/readyz` может быть упрощенным (без проверок зависимостей), как зафиксировано в `TASK.md`.
- Контракт OpenAPI должен меняться в одном изменении вместе с кодом.

## Порядок работ (шаги)
1. Проверить текущие маршруты и покрытие тестами в `internal/httpapi`.
2. Добавить публичные обработчики `GET /healthz` и `GET /readyz` без JWT-требований.
3. Зафиксировать временный характер simplified readiness в коде и в OpenAPI.
4. Обновить/добавить тесты на новые маршруты и ключевые ответы.
5. Прогнать проверки из задачи (`go vet`, `go test`, `make openapi-lint`, `make docs-build`).
6. Подготовить отчёт `REPORT.md` по шаблону.

## Затрагиваемые области
| Область | Что меняется (кратко) |
|--------|------------------------|
| Backend (Go) | Регистрация и обработчики `/healthz` и `/readyz` |
| Frontend | Не затрагивается |
| БД / Atlas | Не затрагивается |
| Инфра / Compose | Не затрагивается |
| Документация / OpenAPI | Синхронизация операций health/readiness и описания readiness |

## Риски и откат
- **Риск:** расхождение фактического JSON-ответа с OpenAPI → **Митигация:** тесты + `make openapi-lint`.
- **Риск:** случайно закрыть health/readiness авторизацией → **Митигация:** регистрация маршрутов как публичных + отдельный тест без JWT.
- Откат: удалить маршруты/правки спецификации отдельным коммитом, откатив только изменения этой задачи.

## Проверка после выполнения
- Команды: `go vet ./...`, `go test ./...`, `make openapi-lint`, `make docs-build`.
- Smoke: `curl -sf http://127.0.0.1:<port>/healthz`, `curl -sf http://127.0.0.1:<port>/readyz`.
