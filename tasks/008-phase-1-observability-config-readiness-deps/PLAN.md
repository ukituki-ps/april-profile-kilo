# План: Фаза 1 (часть 5) — логи, request_id, readiness, env-конфиг

- **Задача:** [`TASK.md`](./TASK.md)
- **Дата плана:** 2026-04-21
- **Статус плана:** черновик

## Исходные допущения
- Реализация остаётся в рамках backend Go (modular monolith), без расширения архитектуры за пределы задачи 008.
- Для readiness используются подключения к PostgreSQL и Redis через env; при отсутствии Redis допускается только явный feature-flag.
- Формат логов должен быть структурированным и безопасным: без утечек секретов/JWT.

## Порядок работ (шаги)
1. Расширить конфиг: обязательные env для БД/Redis, таймауты readiness, feature-flag мягкого режима Redis.
2. Добавить инициализацию зависимостей в `app.Run`: PostgreSQL pool и Redis client с корректным shutdown.
3. Реализовать middleware `request_id` (генерация/проброс `X-Request-Id`) и HTTP-логирование в структурированном формате.
4. Переделать `/readyz` на фактические проверки БД и Redis, возвращать `503` при неготовности.
5. Обновить тесты backend для request_id/readiness и ошибок конфигурации.
6. Актуализировать `.env.example`, OpenAPI (при необходимости 503 body), task docs-site и `REPORT.md`.

## Затрагиваемые области
| Область | Что меняется (кратко) |
|--------|------------------------|
| Backend (Go) | middleware `request_id`, структурное логирование, readiness checks |
| Frontend | Без изменений |
| БД / Atlas | Миграции не требуются |
| Инфра / Compose | env для DB/Redis в compose и примерах |
| Документация / OpenAPI | Обновление readiness контракта и task-story 008 |

## Риски и откат
- **Риск:** Сервис не стартует без обязательных env → **Митигация:** понятные ошибки валидации и обновлённый `.env.example`.
- **Риск:** Ложные 503 из-за сетевых задержек → **Митигация:** настраиваемые таймауты readiness через env.
- **Риск:** Redis не доступен на некоторых dev-стендах → **Митигация:** явный feature-flag soft-mode (по умолчанию strict).
- При необходимости отката: revert изменений по задаче 008; schema/data rollback не нужен (миграций нет).

## Проверка после выполнения
- Команды: `go vet ./...`, `go test ./...`, `make openapi-lint`, `make docs-build`.
- Ручная проверка: запустить сервис, проверить заголовок/лог `request_id`, убедиться что `/readyz` возвращает `503` при недоступной БД/Redis.
