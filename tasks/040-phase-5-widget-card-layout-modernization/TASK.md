# Задача 040: переделать `widget-card` под новый двухколоночный UX

## Мета
- **ID / ветка:** `feature/task-040-widget-card-layout-modernization`
- **Приоритет:** высокий
- **Связанные документы:** [`task_list.md`](../../task_list.md), [`tasks/025-phase-4a-profile-profiles-list-crud-widget/TASK.md`](../025-phase-4a-profile-profiles-list-crud-widget/TASK.md), [`docs/FRONTEND_STRATEGY.md`](../../docs/FRONTEND_STRATEGY.md), [`docs/WIDGET_CONTRACTS.md`](../../docs/WIDGET_CONTRACTS.md)

## Цель
Перестроить `widget-card` в формат master-detail: слева колонка списка профилей (`Card List Column`) с поиском, фильтрацией и пагинацией, справа карточка выбранного профиля на просмотр/редактирование, а создание нового профиля вынести в модальное окно, открываемое по кнопке "плюс".

## Контекст для агента
- Опора на [`docs/AGENT_ARCHITECTURE_CONTEXT.md`](../../docs/AGENT_ARCHITECTURE_CONTEXT.md) и [`README.md`](../../README.md).
- Переиспользовать существующие паттерны и наработки из `ProfilesListWidget` и текущего `widget-card`, чтобы избежать дублирования API-логики.
- DS-first: для левой части использовать компонент `CardListColumn` из `@april/ui`, а не локальную самописную колонку (если нет блокирующего ограничения).
- Сохранить совместимость с текущим BFF/OIDC-контуром AprilHub (tenant/RBAC остаются серверной ответственностью).

## Входит в объём
- Переработка layout `widget-card` в пропорции 25/75:
  - левая колонка (`Card List Column`) для списка профилей;
  - правая область для карточки выбранного профиля.
- В левой колонке реализовать:
  - поиск по профилям;
  - фильтрацию (по существующим доступным полям/типам);
  - пагинацию/дозагрузку списка в паттерне `CardListColumn`;
  - явное состояние выбора текущего профиля.
- В правой области реализовать:
  - режим просмотра данных выбранного профиля;
  - режим редактирования профиля с сохранением через текущий API-контур;
  - корректные `loading/empty/error` состояния.
- Добавить создание нового профиля через модальное окно:
  - открытие по кнопке "плюс";
  - валидация и отправка формы;
  - обновление списка и выбор созданного профиля после успешного создания.
- Обновить документацию/README по контракту `widget-card` и пользовательскому сценарию.
- Добавить/обновить unit/RTL тесты для ключевых сценариев (выбор профиля, пагинация/фильтр/поиск, edit, create через модалку, ошибки API).

## Не входит в объём
- Изменение backend-контрактов и OpenAPI, если текущего API достаточно для реализации.
- Изменение авторизационной модели (RBAC/ABAC) и обход tenant-контекста на фронтенде.
- Редизайн смежных виджетов, не относящихся к `widget-card`.

## Технические ограничения
- Стек: React + TypeScript + Vite + Mantine в рамках текущей архитектуры репозитория.
- Приоритет использования компонентов/patterns из `@april/ui` (DisignApril); кастомный UI только при документированном исключении.
- Не дублировать бизнес-логику прав на клиенте; источник прав и ограничений — backend/Keycloak/BFF.
- Состояния списка и карточки должны быть синхронизированы (изменения справа консистентно отражаются слева).
- Секреты/URL окружений не хардкодить, использовать существующую env-конфигурацию.

## Критерии готовности (acceptance)
- [x] `widget-card` визуально и функционально работает в схеме 25% (список) / 75% (карточка).
- [x] В `Card List Column` работают поиск, фильтрация и пагинация/дозагрузка списка.
- [x] Выбор профиля в левой колонке открывает соответствующую карточку справа в режиме просмотра/редактирования.
- [x] Создание профиля доступно через модальное окно по кнопке "плюс" и после успеха отражается в списке.
- [x] Для основных API-ошибок есть понятное UX-поведение без утечки внутренних деталей.
- [x] Обновлены тесты и документация виджета.
- [x] Левая колонка реализована через `@april/ui` `CardListColumn` (или зафиксировано документированное исключение с причинами).
