# План: Фаза 4a.1 — `ProfilesListWidget` и базовый CRUD

- **Задача:** [`TASK.md`](./TASK.md)
- **Дата плана:** 2026-04-24
- **Статус плана:** согласован и выполнен

## Исходные допущения
- Работа ограничена AprilProfile (`@april/profile-ui`, demo shell, тесты и документация); интеграция в AprilHub остаётся в задаче `026`.
- Текущий OpenAPI фазы 2 содержит CRUD для отдельных профилей (`POST/GET/PUT/DELETE /v1/entities`), но не даёт отдельный list endpoint; список строится из входного набора `entityIds` с клиентскими search/filter/pagination.
- IAM/RBAC остаются на стороне Keycloak/BFF и backend API; UI только безопасно отображает ошибки `401/403/409`.

## Порядок работ (шаги)
1. Добавить `ProfilesListWidget` в `@april/profile-ui` с состояниями `loading/empty/error`.
2. Реализовать операции create/update/delete через существующий OpenAPI-клиент `ProfilesService`.
3. Добавить поиск, фильтр по типу и клиентскую пагинацию, не меняя backend-контракт.
4. Покрыть виджет тестами Vitest/RTL + MSW на happy-path CRUD и предсказуемые ошибки `401/403/409`.
5. Обновить публичный контракт (`README` пакета), demo shell и экспорт пакета.
6. Подготовить docs-site story, обновить обзор и отчёт `REPORT.md` по шаблону.

## Риски и откат
- **Риск:** отсутствие server-side list/search/pagination может ограничить производительность на больших объёмах. **Митигация:** явно зафиксировать ограничение в отчёте и оставить расширение API на follow-up.
- **Риск:** backend сообщения об ошибках могут быть слишком подробными. **Митигация:** в UI показываются нормализованные безопасные тексты для `401/403/409`.
- **Откат:** удалить `ProfilesListWidget` и связанные экспорт/демо-документацию, вернуть пакет к состоянию задачи `022`.
